# SEO Content and GEO Strategy

## Objective

Build durable organic visibility around the six editorial topics already used by Code & Consequence without fragmenting authority across many near-duplicate pages.

The strategy treats the existing topic URLs as canonical pillar pages. Each pillar answers broad user questions directly, exposes related concepts in natural language, and connects readers to the observatory's verified editorial corpus.

## Core principle

Do not create separate pages for every query variation. Maintain one substantial page per editorial topic and let reporting, initiatives, organizations, sources and data provide the depth beneath it.

## Page model

Every pillar should contain:

1. A descriptive title and meta description using natural user language.
2. A concise editorial taxonomy label that preserves the site's information architecture.
3. A substantive overview that defines the topic and explains why it matters to the observatory.
4. Three direct questions with self-contained answers.
5. Natural-language related concepts.
6. Corpus-derived metrics.
7. Links to relevant editorial publications.
8. Links to verified initiatives.
9. Links to adjacent pillar topics.
10. Links to Radar and Data for comparative exploration.

Questions are visible editorial content. They are not marked up as FAQPage because Google discontinued FAQ rich results in 2026.

## Editorial expansion rules

New content should deepen an existing pillar before creating a new taxonomy page.

Create a new standalone page only when all of the following are true:

- the subject has a distinct user intent that cannot be satisfied by an existing pillar;
- the observatory has enough original reporting, verified records or data to support it;
- the page can remain useful after the immediate news cycle;
- the page will have a clear internal-linking role;
- the page will not substantially duplicate an existing topic page.

Avoid programmatic pages that merely swap keywords, jurisdictions or question wording.

## GEO principles

GEO work should improve retrieval and citation without compromising editorial usefulness.

Priorities:

- direct definitions and self-contained explanations;
- clear entity names and relationships;
- visible provenance and source links;
- explicit publication and verification dates where available;
- canonical URLs and hreflang;
- structured data that matches visible content;
- crawlable internal links;
- concise, descriptive headings.

The existing `llms.txt` file is maintained as an auxiliary discovery surface for systems that choose to use it. It is not treated as a Google ranking factor.

## Measurement

### Google Search

Use Search Console to monitor:

- impressions and clicks by pillar;
- queries that reach each pillar;
- country and device distribution;
- indexing and canonical status;
- generative AI visibility reports when available;
- pages receiving impressions but weak click-through rates;
- queries where an existing pillar ranks but does not yet answer the intent well.

### ChatGPT and other generative systems

In analytics, segment referral traffic from ChatGPT. OpenAI documents that ChatGPT Search referral URLs include `utm_source=chatgpt.com`.

Measure:

- sessions referred from generative search;
- landing pages receiving that traffic;
- engagement with source, initiative and topic links;
- whether high-value pillar pages become common entry points.

### Editorial quality

SEO success should not be measured only by traffic. Track whether pages also:

- send users deeper into verified records;
- expose primary-source provenance;
- remain accurate as the corpus changes;
- avoid unsupported claims;
- preserve bilingual parity.

## Next content layer

After Search Console accumulates enough query data, expand selectively through evidence-led subguides. Likely candidates should emerge from real impressions, not from speculative keyword multiplication.

Examples of potential future subguides include:

- AI audits and impact assessments;
- AI data centers and water use;
- AI and public-sector decision-making;
- algorithmic bias and discrimination;
- AI evaluations and independent testing;
- AI automation by task rather than broad job-loss predictions.

These should only be created when the corpus can support a useful, differentiated page.
